# 接口契约与命令行为

## 1. 接口分层建议
### Query 接口
- 只负责读
- 不修改状态
- 可命中缓存

### Command 接口
- 负责刷新、重建、导入、提交等动作
- 应明确是否异步
- 必须返回任务状态或执行结果

## 2. 当前核心接口能力抽象
### 2.1 订单池查询
#### 能力
- 查询生产订单列表
- 支持筛选与详情入口

#### 建议接口
- `GET /api/orders`
- `GET /api/orders/{order_no}`

### 2.2 根层生产用料清单查询
#### 能力
- 查询订单根层子物料
- 返回页面所需聚合字段

#### 建议接口
- `GET /api/orders/{order_no}/materials`

#### 参数
- `refresh_sub_materials: bool = false`
- `refresh_inventory: bool = false`

### 2.3 自制子物料展开
#### 能力
- 基于 `parent_material_code` 展开下一层 BOM 子项

#### 建议接口
- `GET /api/materials/{parent_material_code}/children`

#### 参数
- `refresh: bool = false`

### 2.4 刷新子物料
#### 语义
- 强制回 ERP 刷新当前订单根层子物料清单
- 覆盖当前缓存版本

#### 建议接口
- `POST /api/orders/{order_no}/materials/refresh`

### 2.5 刷新自制
#### 语义
- 刷新当前订单或当前页面涉及的自制子物料子树

#### 建议接口
- `POST /api/orders/{order_no}/self-made-materials/refresh`

### 2.6 刷新库存
#### 语义
- 强制刷新库存缓存
- 再回填当前清单和展开树上的库存列

#### 建议接口
- `POST /api/inventory/refresh`
- 或 `POST /api/orders/{order_no}/inventory/refresh`

## 3. 命令行为定义
### 刷新子物料
- 前置条件：订单存在
- 执行：重新查询 ERP 子物料清单
- 落库：覆盖该订单当前版本
- 影响：根层清单缓存失效并重建

### 刷新自制
- 前置条件：页面存在自制子项
- 执行：对自制子树逐项重建
- 落库：覆盖 `parent_material_code` 维度当前版本
- 影响：展开树缓存失效并重建

### 刷新库存
- 前置条件：ERP 库存接口可用
- 执行：刷新库存快照
- 落库：按 `material_code` 覆盖当前版本
- 影响：所有依赖库存列的页面查询结果需重新聚合

## 4. 接口返回原则
- 不返回模糊成功
- 错误时返回明确失败原因
- 长任务返回任务状态 ID
- 聚合查询返回正式字段，不返回页面临时拼接字段

## 5. 重写建议
- FastAPI 中明确分 `routers/query` 与 `routers/command`
- React 中 query/mutation 解耦
- 所有刷新接口统一支持任务状态查询
