## Goal
Replace every user-visible fragment that currently renders as mojibake, English text, or informal wording in the Next.js frontend with polished, formal Chinese copy so the product feels consistent and professional to Chinese-speaking planners.

## Scope
- Sidebar navigation labels, application metadata, and any other copy that ships from `fronted/src/legacy` (page titles, form labels, button text, dropdown options) that the scheduler or workshop-manager UI renders directly.
- The specific flows called out by the user: scheduler dashboard, daily capacity, test tools, and the rendered schedule calendar page heading, along with their shared layout and metadata.
- Playwright-based browser validation that inspects the actual rendered copy after the change.

## Non-Goals
- Backend API or schema changes, even if they influence localized field names, unless they are surfaced directly as user-facing text.
- Introducing fallback copy or bilingual variants; the instructions explicitly forbid silent fallback paths.
- Adjusting non-user-facing constants or logs that never render in the UI.

## Preconditions
- Node.js 20+ and `npm install` executed inside `fronted` so that Next.js can build and Playwright can run.
- The backend service and SQLite test database access (`PRODUCTION_PLAN_E2E_DB_PATH`) must be available to reproduce the UI that exposes the copy under test.
- Access to UX/product guidance on formal Chinese tone; lacking that, default to the terminology already used in existing Chinese strings in the repo.

## Impacted Areas
- `fronted/src/legacy/App.jsx` (sidebar nav, logout button text) and `fronted/src/app/layout.tsx` metadata.
- Main pages: `SchedulerDashboardPage.jsx`, `DailyCapacityPage.jsx`, `TestToolsPage.jsx`, `ScheduleCalendarPage.jsx`, plus any chart or shared component that feeds into their rendered headings, toolbar copy, or accessibility labels.
- Playwright spec files under `fronted/tests/e2e` that will assert the updated copy to prevent regression.

## Phase Plan

### P1: Copy audit and replacement

- Objective: Identify every English/garbled/informal string in the targeted pages, decide the formal Chinese phrase for each slot (e.g., `Top 5/8/10/15` → `前五名/前八名/前十名/前十五名`), and implement the replacements in the React source so that Next.js outputs clean Chinese characters.
- Owned paths: `fronted/src/legacy/App.jsx`, `fronted/src/app/layout.tsx`, `fronted/src/legacy/pages` (the dashboard, test tools, daily capacity, calendar header, and any shared components those files import).
- Dependencies: Finalized wording decisions (use existing professional terms from the repo where available) and a Next.js development build for sanity-checking the rendered copy.
- Deliverables: Updated JSX strings, a short note in `execution-log.md` listing the old vs. new text for each affected area, and a reviewable diff that can be eyeballed in a real browser.

### P2: Real-browser copy validation

- Objective: Validate the correctness of the new Chinese copy in Chromium-powered Playwright runs so we can prove that English/garbled text never sneaks back in through stale builds or caching.
- Owned paths: `fronted/tests/e2e` (new or updated copy-verification `.spec.ts`), plus `execution-log.md` entries capturing commands and evidence (screenshots/videos) generated by Playwright.
- Dependencies: The Playwright config (`fronted/playwright.config.ts`) to launch the backend + frontend, and the scheduler/test accounts from `fronted/tests/e2e/support`.
- Deliverables: A targeted copy verification spec that checks every navbar item, heading, dropdown option, and button text mentioned in P1, accompanied by Playwright artifacts (screenshots or videos) referenced in `test-report.md`.
