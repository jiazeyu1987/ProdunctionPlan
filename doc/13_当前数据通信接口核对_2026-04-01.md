# 当前数据通信接口核对
日期：2026-04-01

## 1. 核对范围
本次只核对三段通信：
- 前端 -> 后端
- 后端 -> SQLite
- 后端 -> ERP

核对依据：
- 当前代码实现
- 当前本地冒烟验证

## 2. 核对结论

### 2.1 前端 -> 后端
结论：运行态正确，当前活跃页面已经统一到 `/api/*`。

已确认正确：
- legacy 页面通过 `NEXT_PUBLIC_BACKEND_BASE_URL` 直连 FastAPI
- 新版 `/api/*` 页面通过 Next 代理转发到 FastAPI
- 当前运行态已经不再依赖前端 mock 数据
- 当前活跃页面的主要查询链路已经切到 `/api/*`
- 当前活跃页面的主要写命令也已经切到 `/api/*`
- 旧的 `/queries/*`、`/internal/v1/internal/*`、`/v1/*` 路由已从运行态移除

当前差异项：
- 开发态请求头里的 `Authorization: Bearer mvp-dev-token` 目前仍未在后端强制校验

### 2.2 后端 -> SQLite
结论：正确。

已确认正确：
- FastAPI 查询接口全部通过 SQLite 返回
- `/api/*` 命令接口只负责写入 `jobs` 表
- worker 可领取 job 并回写业务表
- 当前落地表覆盖了可见页面所需数据

当前差异项：
- 后端内部仍有 `LegacyAppService` 等历史命名，但这不再影响对外接口形态

### 2.3 后端 -> ERP
结论：接口定义正确，真实连通性取决于部署配置。

已确认正确：
- ERP 基础地址、路径、超时、鉴权都已参数化
- 根层用料、自制子项、库存、供应属性、订单同步都有独立网关
- ERP 返回结构校验已落地
- 配置缺失时会 fail-fast，不会使用 mock

当前差异项：
- 未配置 ERP 环境变量时，相关调用会返回 `ERP_BASE_URL_MISSING`
- 订单同步脚本仍是后端批处理入口，不属于 HTTP job 接口

## 3. 当前接口错误清单
本次未发现已上线链路中存在以下硬错误：

- 字段名写错
- 数据库目标写错
- 前端误连 mock 数据源

当前已经确认移除的历史接口族：
- `/queries/*`
- `/internal/v1/internal/*`
- `/v1/*`
